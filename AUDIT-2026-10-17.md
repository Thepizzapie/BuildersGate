  test personas, not real people.
- **`100.64.0.9` (31×)** — Tailscale CGNAT range in `tests/test_remote_guard.py`, exercising

- **CI workflows** — all credentials via `${{ secrets.* }}`. No hardcoded values.

### One action item

## 2. Code Quality

### Strengths (unusual, worth preserving)

- **7,227 tests pass, 0 failures** (90 skipped, 318 slow-deselected; 6m27s).
- **Test mass ≈ 47% of source LOC** (311 test files vs 316 source files).
- **Dependency floors are treated as a security control** — `pyproject.toml` documents
  that a floor is what a constrained resolver actually serves, and `security.yml`
  audits *both* the resolved tree **and** the floors pinned exactly, because a
  floor-only vulnerability is invisible to a resolved-tree audit. This is a real gap
  in most projects and it is closed here.
- **Least-privilege CI** — `permissions: contents: read` on every workflow, no
  `pull_request_target`, no script injection via `github.event.*`, CodeQL weekly.
- **Candid `SECURITY.md`** with an honest threat model (loopback is not a boundary,
  DNS-rebinding host allowlist).
- **Almost no dead code** — 5 unused locals in 184k lines (vulture, 100% confidence).
- **Deliberate fail-safe design** — `auto_approve` is accepted and ignored in
  `runners.py`; workers run `approval_policy = never` because "a reviewer is a thing
  it can persuade." Correct call, well documented.

### Issues

#### 🔴 1. CI lint is failing on `main` right now
Reproduced on a clean checkout of `2fc83d6` with the **exact CI-pinned ruff (0.12.12)**:

```
src/bgate_core/qa/agentplay.py:31:25: F401 `typing.Optional` imported but unused
src/bgate_core/qa/feel.py:38:25:      F401 `typing.Optional` imported but unused
tests/board/test_fast_track.py:9:8:   F401 `pytest` imported but unused
Found 3 errors. [*] 3 fixable with the `--fix` option.
```

The `lint` job runs `ruff check --output-format=github .`, so it is red. Auto-fixable.

#### 🔴 2. A known high-severity frontend advisory is open and unactioned
GitHub's own alerting *has* caught this — the push of this report returned:

> `GitHub found 1 vulnerability on Thepizzapie/BuildersGate's default branch (1 high)`
> — [dependabot alert #11](https://github.com/Thepizzapie/BuildersGate/security/dependabot/11)

So the gap is not detection, it is that **nothing acts on the detection**. Dependabot
*alerts* (vulnerability detection) are enabled, but Dependabot *version updates* and CI
gating are configured for Python only:

- **`.github/dependabot.yml` covers `pip` and `github-actions` — not `npm`.**
  So no update PR is ever opened for `frontend/`, and the alert sits.
- **`security.yml` runs `pip-audit` twice but never `npm audit`.**
  So no build fails on it either.
- CI *does* `npm ci` + `npm run build` (the `frontend-drift` job), so the tooling is
  already present — only the audit step is missing.

**Live result:** `npm audit` reports **1 high severity** vulnerability:

| | |
|---|---|
| Package | `source-map-js` 1.2.1 (via `postcss` 8.5.26) |
| Advisory | [GHSA-68fv-2mgg-jv7q](https://github.com/advisories/GHSA-68fv-2mgg-jv7q) — event-loop DoS via indexed source-map section offsets |
| Severity | High |
| Fix | `source-map-js` **1.2.2** |

**The fix is a lockfile refresh with zero `package.json` churn** — `postcss` requires
`^1.2.1`, which already admits 1.2.2.

*Honest impact note:* this is build-time tooling, not shipped runtime code, so real
exposure is low. The finding is the **asymmetry** — for Python this class of issue is
caught *and* routed into a PR and a failing build; for JS it is caught and then ignored.
An open alert nobody is paged by is the part worth fixing.

#### 🟠 3. Pillow 14 will break 31 production call sites
`Image.getdata()` is deprecated and **removed in Pillow 14 (2027-10-15)**. The test run
emitted 41 such warnings. `pyproject.toml` declares `Pillow>=12.3.0` with **no upper
bound**, so a future `pip install builders-gate` resolves to a Pillow that breaks it.

- **31 call sites in `src/`** (production), 19 in tests.
- Affected paths: `art/chroma.py`, `art/framegate.py`, `art/tilemask.py`,
  `level/roomqa.py`, `cine/cinecut.py`, `adapters/sprites.py`, `adapters/blender.py`,
  `mcp/server.py` (6 sites).

This is the mirror image of the project's own floor discipline: the *floor* is managed
carefully, but there is no *ceiling* for a known-breaking major.

#### 🟠 4. `server.py` is 11,080 lines, and the extraction pattern is circular
A `tools_*.py` split already exists (10 modules), but it is wired via **bottom-of-file
star imports with a deliberate import cycle**: `server.py` star-imports the tools
modules at line 10810+, and all 10 modules import back from `server`. A comment at
`server.py:48` records the failure mode ("the star imports while `tools_blender` is
still half-initialized").

**The cycle is only 3–4 symbols wide:** `_root`, `_tool`, `_work_item_id`, `_re`.

`server.py` still holds ~204 tool definitions with clean domain seams already visible:
`queue_` (15), `godot_` (11), `scene_` (9), `playtest_` (9), `music_` (9),
`greenlight_` (9), `sprite_` (7), `cutout_` (7).

#### 🟡 5. 28 pure-Python pixel loops remain (the fix is already proven in-repo)
`src/bgate_core/art/spritekit.py` documents this exact problem and its solution:

> EVERY LOOP IN HERE IS A BAND OPERATION WHERE PILLOW HAS ONE. This runs over whole
> sheets on the same worker thread that holds the MCP call, and the mass measurement
> it replaces (`sum(1 for px in img.getdata() if px[3] > 60)`) walked **1.5 million
> Python tuples per frame**.

The pattern was fixed there but **28 `list(getdata())` / per-pixel loops remain
elsewhere in `src/`**, on the thread that holds the MCP call. `numpy` is already a
declared dependency and is used in only 8 files.

#### 🟡 6. `npm run typecheck` is defined but never run in CI
`frontend/package.json` declares a `typecheck` script. No workflow invokes it, so
TypeScript errors reach `main` as long as `vite build` succeeds.

#### 🟡 7. Minor
- Third-party actions pinned by major tag, not SHA. Worth SHA-pinning the two that
  touch releases and signing credentials: `softprops/action-gh-release@v2`,
  `azure/trusted-signing-action@v0`.
- `dispatch.py:1305` still computes and passes `auto_approve=` into `_codex_args`,
  where it is intentionally ignored. Dead argument at the call site.
- 5 unused locals: `recorder.py:530`, `cutoutkit.py:670`, `server.py:5136`,
  `runners.py:256,326`.

## 3. Suggested Enhancements (prioritized)

### 1. Close the JavaScript dependency gap — *security, ~15 min*
Three small changes, one of which fixes a live high-severity advisory:
```yaml
# .github/dependabot.yml
  - package-ecosystem: "npm"
    directory: "/frontend"
    schedule: { interval: "weekly" }
    labels: ["dependencies"]
```
```yaml
# .github/workflows/security.yml — new job
  npm-deps:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "20", cache: npm, cache-dependency-path: frontend/package-lock.json }
      - run: npm ci --prefix frontend
      - run: npm audit --audit-level=high --prefix frontend
```
Then `cd frontend && npm audit fix` to take `source-map-js` 1.2.2 (lockfile only).

**Why first:** it is the only *currently exploitable-class* finding, it is already an
open alert rather than a hypothetical, the fix is non-breaking, and it extends the
dependency discipline the project already applies to Python to the half of the codebase
that lacks it.

### 2. Unbreak CI lint — *maintainability, ~2 min*
```bash
ruff check --fix .   # removes the 3 unused imports
```
**Why:** a red gate on `main` is how teams learn to ignore the gate — the same
argument `security.yml` already makes about CodeQL's 277-alert suite.

### 3. Cap Pillow and retire `getdata()` — *maintainability + performance, two-for-one*
Immediately: `"Pillow>=12.3.0,<14"` in `pyproject.toml`, with a comment pointing at the
2027-10-15 removal (mirroring the existing floor rationale).

Then migrate the 31 production call sites to Pillow band operations or `numpy`
(`np.asarray(im)`). This **simultaneously** removes the Pillow 14 breakage and the
per-pixel Python overhead from issue 5 — the same lines cause both, and `spritekit.py`
already demonstrates the target idiom and the payoff.

### 4. Break the import cycle, then continue the `tools_*` split — *maintainability*
Move the 3–4 shared symbols (`_root`, `_tool`, `_work_item_id`, `_re`) into a new
`src/bgate_mcp/_shared.py` that both `server.py` and every `tools_*.py` import. That
converts 10 circular edges into 10 acyclic ones and lets the bottom-of-file star
imports be deleted.

Only then split `server.py` along the seams that already exist — `tools_queue.py`,
`tools_godot.py`, `tools_scene.py`, `tools_music.py`, `tools_greenlight.py`. Doing this
*before* breaking the cycle would deepen it, which is likely why it stalled.

### 5. Run the typecheck you already wrote, and SHA-pin release actions — *low cost*
Add `npm run typecheck` to the existing `frontend-drift` job (node is already set up
there — one line). SHA-pin `softprops/action-gh-release@v2` and
`azure/trusted-signing-action@v0`, the two third-party actions that handle release
artifacts and Azure signing credentials.

## Bottom line

**No secrets, credentials, or PII are exposed** — verified across the complete
599-commit history, not just the shallow clone this audit started from. Security
engineering here is well above average: audited dependency floors, least-privilege CI,
a working secret-redaction filter, an honest threat model, and a documented decision to
remove an auto-approval path rather than guard it.

Two gaps are worth acting on now, and both are small: **an open high-severity frontend
advisory (dependabot alert #11) that nothing is configured to act on**, and **CI lint is
red on `main` over three unused imports**. The larger items — the Pillow 14 ceiling, the
11k-line `server.py` and its import cycle — are scheduled work, not emergencies.
