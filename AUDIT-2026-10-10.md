## 2. Code Quality

### 2a. `main` is red, and the fix already exists on an unmerged branch — top priority

**5 of 7 CI jobs fail on `main`**, and have since 2026-10-03 across three consecutive runs
(293, 292, 289). Only `lint` and `wheel-smoke` pass.

| Job | Status |
|---|---|
| `pytest (windows, py3.11)` | ❌ |
| `pytest (windows, py3.12)` | ❌ |
| `pytest (linux, advisory)` | ❌ |
| `frontend-drift` | ❌ |
| `browser-smoke` | ❌ |
| `lint`, `wheel-smoke` | ✅ |

All of it reduces to **two defects with one shared root**, and **both are already fixed** by commit
`0c993db` sitting on `origin/claude/confident-johnson-0cbpmz` — **which has no open PR** (the only
open PR is #78, unrelated). The fix is one commit, 2 files, a pure rename plus a test assertion.

**Defect 1 — a filename case collision that ships a broken UI pane to Linux users.**
`src/bgate_ui/static/dist/bgate.js` lazily imports `./bgate-Floor.js` (capital F, twice), but the
committed tree carries the chunk as **`bgate-floor.js`** (lowercase). Vite derives the chunk name
from the component (`frontend/src/shell/Floor.tsx`) via
`chunkFileNames: "dist/bgate-[name].js"`, so the build emits capital-F; on the maintainer's
case-insensitive filesystem that write landed on the existing lowercase directory entry without
changing its case, so the rename never reached git and the dev machine resolved the import anyway.
On a case-sensitive filesystem the import 404s and the Floor pane renders
*"This screen could not load"*. `pyproject.toml` ships `bgate_ui = ["static/**/*"]` as package
data, so **this is in the wheel** — every Linux `pip install builders-gate` gets a broken Floor
pane. This is what `browser-smoke` has been reporting, and `frontend-drift` misread the absent
capital-F name as a "0-byte stale chunk" (its diagnostic does `git show HEAD:<name>` and prints an
empty result as `committed 0B` — see 2c).

**Defect 2 — a stale test assertion.** Commit `12598d7` ("Playtests play web projects") changed the
`/play/` empty-build 404 at `src/bgate_ui/app.py:2180` from `"no web build — export it first
(tech seat)"` to `"no build to play yet — press Rebuild"`, because a web project has no `export/`
directory to point at. `tests/ui/test_queue.py:269` still asserts `"export" in …message`. Verified
locally: **1 failed, 7177 passed** — this single assertion is the entire pytest failure on all
three platforms.

I verified `0c993db` in a scratch worktree: `bgate-Floor.js` present at the correct 1891 bytes,
and `tests/ui/test_queue.py` goes **40 passed**. **Recommended action: land that branch on `main`.**
I have not merged or pushed it — that is an outward-facing change this audit did not ask for.

### 2c. Test coverage: strong, with one misleading diagnostic

7,178 collected tests (7,177 passing), 86,828 lines of test code against 183,099 of source — a
~0.47 ratio, healthy for a project this size. Nightly job covers the real Blender/Godot paths the
daily gate deselects. No coverage gap worth flagging.

The one weakness is a **diagnostic**, not a gap: `frontend-drift`'s failure message
(`ci.yml:104–118`) reports a path that exists in the fresh build but not in `HEAD` as
`committed 0B … stale`, because it pipes `git show HEAD:<name>` straight into a length. That cost
real debugging time here and, per the commit message, on the maintainer's side too. Have it
distinguish *absent in HEAD* (likely a case-only rename) from *present but differing*.

### 2d. Dependencies

The Python side is audited unusually well: `security.yml` runs `pip-audit` against both the
**resolved tree** and the **pinned floors** (a floor-only vulnerability being invisible to a
resolved run is a real and rarely-handled subtlety), plus CodeQL, plus Dependabot for `pip` and
`github-actions`. Credit where due. Three gaps:

1. **The frontend has no dependency security coverage at all.** `.github/dependabot.yml` declares
   `pip` and `github-actions` — **no `npm` ecosystem** — and `security.yml` has no `npm audit` step,
   and CodeQL is `languages: python` only. `frontend/package-lock.json` is committed, so this is
   scannable and simply unscanned. `npm audit` right now reports **1 high-severity advisory**:
   `source-map-js` ≤1.2.1, event-loop DoS (GHSA-68fv-2mgg-jv7q), reachable via the Vite/PostCSS
   build chain. Build-time-only, so the practical risk is low — but it is exactly the class of thing
   the Python side is wired to catch automatically and the TypeScript half is not. ~145 npm packages
   and 118 `.ts`/`.tsx` files sit outside every scanner.
2. **Deprecated GitHub Actions.** `actions/checkout@v4` (11 uses) and `actions/setup-node@v4`
   (7 uses) target Node 20 and are already being force-run on Node 24 — every CI run emits the
   deprecation warning. Bump to current majors.
3. **`Pillow>=12.3.0` is uncapped while 10 source call sites use a deprecated API.**
   `Image.getdata()` is deprecated and **removed in Pillow 14 (2027-10-15)**. The test run emitted
   these warnings from source, not just tests — `bgate_core/level/roomqa.py:282`,
   `bgate_core/cine/cinecut.py:621`, `bgate_adapters/blender.py:2082`,
   `bgate_adapters/sprites.py:168,389`, and five sites in `bgate_mcp/server.py`. Not urgent; it is a
   dated, known breakage, which makes it cheap to retire now rather than rediscover in 2027.

### 2e. Architecture note

`src/bgate_mcp/server.py` is **11,064 lines** — roughly 2.7× the next largest file
(`bgate_adapters/blender.py`, 6,458) and the single biggest maintainability liability in the tree.
It mixes MCP tool registration with image analysis helpers (`_palette_hist`, `_pal`, the pose
gates). The adjacent `tools_level.py` (2,477 lines) shows the extraction pattern already exists;
the image-analysis helpers are the natural first slice to move out.

## 3. Suggested Enhancements — prioritized

**1. Land `0c993db` on `main`. (Security-adjacent: ships a broken artifact; highest impact.)**
One commit, 2 files, verified green. It turns 5 red CI jobs green and stops shipping a broken Floor
pane in every Linux wheel. Nothing else on this list matters while `main` is red, because a
permanently-red gate is a gate people stop reading — the same argument `security.yml` makes for
narrowing CodeQL.

**2. Close the frontend security-coverage gap. (Security.)**
Three small edits, each independently worthwhile:
- add an `npm` ecosystem block to `.github/dependabot.yml` for `/frontend`;
- add an `npm audit --audit-level=high` step to `security.yml`;
- add `javascript-typescript` to the CodeQL `languages` list.
Then clear the existing `source-map-js` advisory with `npm audit fix`. Today a frontend CVE has no
path to anyone's attention.

**3. Make the case-collision class of bug impossible to reintroduce. (Maintainability.)**
This bug was invisible on the maintainer's platform by construction, and `CLAUDE.md` names Windows
as the supported one — so it *will* recur. Pick either: set `chunkFileNames` to lowercase the
`[name]` token so chunk filenames stop inheriting component capitalization, or add a CI step that
fails when two tracked paths differ only by case. Pair it with the `frontend-drift` diagnostic fix
from 2c so the next occurrence names itself instead of reading as "0 bytes".

**4. Retire `Image.getdata()` across the 10 source call sites. (Maintainability + a real
performance win in one spot.)**
Removes a dated breakage (Pillow 14, 2027-10-15) ahead of time. Most sites thumbnail first and are
cheap, so this is mainly forward-compatibility — **except `blender.py:2082`
(`_exposure_report`)**, which is the one genuinely full-resolution path: it materializes an entire
render as a Python list of RGBA tuples, then builds two more full-length lists (`subject`, `luma`)
and makes three more passes. I benchmarked the exact code at 1920×1080: **1.52s → 0.46s, a measured
3× speedup** with bit-identical outputs (blown/clipped/mean matched to 6 decimals), plus a large
drop in peak memory from not holding ~2M tuples. numpy is already a hard dependency and already
imported in `server.py`. A modest win, honestly measured — worth taking because the migration has
to happen anyway.

**5. Housekeeping. (Low effort, low risk.)**
Fix `.gitignore:54` to use forward slashes and `git rm --cached
.github/instructions/codacy.instructions.md`; bump `actions/checkout` and `actions/setup-node` off
deprecated Node 20; confirm GitHub secret scanning + push protection are on; rotate the
historically-leaked key if that was never done; set `user.email` to the noreply address on the Mac
Studio machine. Optionally begin slicing the image-analysis helpers out of the 11k-line
`server.py`.

### Bottom line

No secrets, no PII, and no private files are exposed — the repo's own scrubber, auth handling, and
Python dependency auditing are all better than typical. The real finding is operational: `main` has
been red for a week across 5 of 7 jobs, one of those failures is shipping a broken UI pane to every
Linux install, and the verified one-commit fix is stranded on a branch with no pull request.
