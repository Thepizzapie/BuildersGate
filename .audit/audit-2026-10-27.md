### Positive controls worth noting
This repo is unusually strong here, and the controls are real, not decorative:
- **`src/bgate_core/board/streamer.py`** — a purpose-built redactor that kills

  email) across *four* path spellings (native, forward-slashed, JSON-escaped,

- **`src/bgate_ui/redact.py`** — applies that redactor as response middleware,
  on both finite bodies and SSE streams.
- Auth guard uses `secrets.compare_digest` (timing-safe) and tokens are written

## 2. Code Quality

### Healthy
- **`ruff check src/ tests/` passes clean** on the project's configured ruleset.
- **6,281 test functions across 333 files.** Missing tests are *not* a problem
  here. I ran `tests/ui tests/store tests/board tests/mcp`: **3,753 passed,
  2 failed, 27 skipped** in 7:00. Both failures are in Windows-shell/timing
  paths and land exactly where `ci.yml`'s `test-linux` job is already
  `continue-on-error: true` by design.
- **CI is genuinely thorough:** a `frontend-drift` job proves the committed
  React bundle matches a fresh `npm run build`; `pip-audit` runs against the
  resolved tree *and* the floors; CodeQL is scoped deliberately after a
  277-alert pass was triaged rather than ignored.
- **No SQL injection.** All 12 f-string `execute()` sites interpolate only
  allowlisted column names (e.g. `_RUN_FIELDS`) or literal table names; every
  value goes through `?` parameters.
- **No path traversal.** `/api/preview` resolves, then enforces
  `relative_to(base)` plus a suffix allowlist — correct order, and correct
  under symlinks.
- `npm audit`: **0 vulnerabilities.** Python floors carry no open advisories.
- The 7 `B023` (closure-over-loop-variable) hits I checked are **false
  positives** — each closure is consumed inside its own iteration.

### Real issues
1. **Dead code with a measurable cost** —
   `src/bgate_core/audio/audiohooks.py:181-183` builds a list `starts` with a
   per-character Python loop over the entire script text, and **never reads
   it**. `line_of()` right below uses `text.count("\n", 0, pos)` instead.
   Measured waste, per scanned file: 5.2 ms / 45 KB, 55 ms / 450 KB.
   `ruff` F841 misses it because the name *is* used — appended to, never read.

2. **`src/bgate_mcp/server.py` is 11,342 lines** — 298 top-level functions, the
   longest being `image_sprites` at **861 lines** and `tileset_generate` at
   **684**. The single largest maintainability liability in the tree.

3. **Python support is declared wider than it is tested.**
   `requires-python = ">=3.11"` has no upper bound, but CI tests only 3.11 and
   3.12. I hit a concrete consequence on 3.13: the declared floor
   `numpy>=1.26` resolves to 1.26.0, which declares `Requires-Python
   >=3.9,<3.13` — so **the floor is uninstallable on Python 3.13+**, and the
   floor-audit job that exists to catch exactly this rot is pinned to 3.12 and
   cannot see it. First 3.13-compatible numpy is 1.26.2.

4. **Vendored third-party JS is invisible to every scanner.**
   `frontend/public/vendor/` holds 3.8 MB of three.js, CodeMirror 5, Tabler
   Icons and JetBrains Mono with **no version marker anywhere** — no
   `package.json`, no `VERSION`, no discoverable `REVISION` in the minified
   three build. Not in any manifest, so `npm audit`, Dependabot and `pip-audit`
   are all blind to it. For a project that treats dependency floors as a
   security control, this is the gap in that control.

## 3. Suggested Enhancements — prioritized

### 1. Bound the email regex in the scrubber (security + performance)
`src/bgate_core/board/streamer.py:273`
```python
_EMAIL = re.compile(r"\b[A-Za-z0-9._%+\-]+@[A-Za-z0-9.\-]+\.[A-Za-z]{2,}\b")
```
The local-part class contains `.`, so on a long unbroken run of
`[A-Za-z0-9.-]` the engine restarts a greedy O(n) scan at every one of n
positions — **quadratic**. Measured:

| input | time |
|---|---|
| 12 KB | 0.32 s |
| 25 KB | 1.09 s |
| 50 KB | 4.37 s |
| 100 KB | **17.6 s** |

This matters because of *where* it runs. `redact.py:_scrub_whole()` drains an
entire response body and hands it to `filt.text()` **as one string** — its own
comment cites "a 1.2 MB `/api/state`". So this is a synchronous,
request-blocking path over megabyte bodies carrying agent transcripts,
playtest telemetry and Twitch chat. It is the same bug class already fixed once
in `qa/feedback.py` (the `py/redos` CodeQL hit documented in `security.yml`).

Fix — RFC 5321 bounds, **behaviourally identical** on every address I tested
(`a@b.com`, `first.last@sub.domain.co.uk`, `x+tag@mail-server.io`, `u%v@a.b.c.dev`,
and the negatives `a@b`, `trailing@dot.`):
```python
_EMAIL = re.compile(r"\b[A-Za-z0-9._%+\-]{1,64}@[A-Za-z0-9.\-]{1,255}\.[A-Za-z]{2,24}\b")
```
Measured result: linear, and **666× faster** at 100 KB (17.6 s → 26 ms).
One line, no behaviour change, removes a latent request-blocking DoS from the
security-critical path.

### 2. Make phone-device revocation mean what the UI says
`src/bgate_ui/remote.py`. `Settings → Connections` presents revoke as a real
per-device control ("revoke refuses one device while the rest keep working"),
and the panel is admirably candid that *forget* is not a revoke. But revoke
itself has two holes:
- **It is keyed on a forgeable identity.** `device_key()` is
  `sha1(f"{ip}|{user_agent}")[:12]`. A revoked phone that changes its
  User-Agent — a browser update, or switching between the in-app web view and
  Safari — or that picks up a new DHCP lease, produces a different key and
  **silently regains full access with its existing token**.
- **It does not survive a restart.** `_devices` is a plain in-memory dict with
  no persistence, while the token file on disk does persist. Revoke a phone,
  restart the dashboard, and the phone works again.

The honest control is `rotate`, which the panel already offers and which does
cut every device off. Either persist revocations and key them on something
stable (issue a per-device token at pairing), or give revoke the same candour
the forget button already gets and point at rotate.

Related, minor: the `MAX_DEVICES` eviction in `remote.py:195-199` only ever
evicts *non-revoked* rows, so a token-holder cycling User-Agents evicts
legitimate devices while revoked rows are retained, and the table can grow past
its cap when all rows are revoked.

### 3. Drop `"testserver"` from the production Host allowlist
`src/bgate_ui/api.py:348`
```python
_LOOPBACK_HOSTS = {"127.0.0.1", "localhost", "::1", "testserver"}
```
The eight lines of comment directly above this set explain, correctly and in
detail, why `0.0.0.0` is excluded — it is the one spelling that reaches the
process while stepping around the browser's private-network protections. That
reasoning is sound, and it is exactly why `testserver` does not belong in the
same set. It is Starlette `TestClient`'s default Host, it carries no
justifying comment, and it is live in production: any request with
`Host: testserver` passes the anti-DNS-rebinding gate. The gate's own
threat model (per the comment at `api.py:466-485`) is a page that scrapes
`window.BGATE_TOKEN` and reaches `POST /api/godot/run` → `OS.execute()` → a
shell as the desktop user. Inject the test host from a fixture, or gate it on
an env var the test harness sets, rather than shipping it.

Same file, lower priority: `_LOOPBACK_PEERS` includes `""`, so a request with
no `request.client` is classified as the desk by `is_desk()`, and an absent
Host header also passes. Both are unreachable under uvicorn, but they are
fail-open defaults inside a security boundary — prefer failing closed.

### 4. Point Dependabot at the frontend
`.github/dependabot.yml` covers `pip` and `github-actions` but **not npm**. The
frontend carries React 19, Vite 6, Mantine 9 and Playwright in
`frontend/package-lock.json`, watched by nothing — and the most recent commit
on this branch is literally *"frontend: clear npm audit highs (vite 6.4.5,
source-map-js 1.2.2)"*, i.e. this was caught and fixed by hand. Add:
```yaml
  - package-ecosystem: "npm"
    directory: "/frontend"
    schedule:
      interval: "weekly"
    open-pull-requests-limit: 5
    labels: ["dependencies"]
```
Then record versions for `frontend/public/vendor/` (Code Quality #4) so the
vendored 3.8 MB is auditable too — a `vendor/VERSIONS.toml` with name, version
and source URL per library is enough to make it greppable against advisories.

### 5. Close the Python-version gap
Pick one and make it true: either cap `requires-python = ">=3.11,<3.14"` to
match what CI actually tests, or add 3.13 to the Windows matrix and raise the
numpy floor to `>=1.26.2` (the first release that installs on 3.13). Right now
the declaration promises 3.13+ support that is untested and, at the floor,
broken. While there: the advisory `test-linux` job is `continue-on-error: true`,
so nobody is obliged to read it — the 2 failures I reproduced may have been red
for a while. Asserting a known-failure baseline would keep accepted failures
tolerated while making *new* Linux regressions visible.

## Summary

No secrets, no PII, no credentials in the working tree or anywhere in history —
confirmed explicitly. Nothing is public that shouldn't be. The security posture
is above average for a public repo of this size: a real redaction layer, a
carefully reasoned anti-DNS-rebinding gate, timing-safe token comparison,
parameterized SQL throughout, correct path containment, and dependency floors
treated as a control with CI to match.

The findings worth acting on are a quadratic regex sitting in the
request-blocking redaction path (one-line fix, 666× measured), a
device-revocation control weaker than its own UI claims, a test hostname left
in a production allowlist, and two coverage gaps — npm and vendored JS outside
Dependabot's view, and a declared Python range wider than the tested one.
