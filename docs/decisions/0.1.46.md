# [0.1.46] - 2026-09-12

Moved verbatim from `CHANGELOG.md`; links inside are as written there, relative to the repository root.

### Added
- **Three engines. `project.engine` decides which tools register, which
  doctor rows are graded, where the scaffolder looks, and what every seat is
  told to verify with.** The column had been in the schema since migration
  0001 with two legal values and exactly one reader: the dispatcher picked a
  sentence for a seat brief. Every `godot_*` tool, every `scene_*` tool and
  the whole level surface registered regardless, so a project recorded as
  `none` still advertised eighteen Godot tools to every agent it dispatched.
  `bgate_core.runtime.engines` is the table that gives the column teeth:
  markers, adapter, doctor rows, template and shared tree, and `ENGINE_TOOLS`,
  the exact names each engine owns. A third gate on `_tool` registers only
  the project's engine's tools, with the same failure rule the module and
  seat gates state: a failed read registers everything, because a missing
  tool must only ever come from a stored decision. Detection order is
  strong markers first (`project.godot`, `ProjectSettings/ProjectVersion.txt`)
  and `package.json` last, because a Godot project with a tooling
  `package.json` is a Godot project.
- **The web engine: vite + TypeScript templates, a dev server, a build with a
  payload budget, vitest, headless screenshots.** It exists because of a
  measurement: a finished Godot 3D game exported to the web at 661 MB, ran,
  and no player would ever have waited for it. `web_build` measures what a
  first visit downloads over the wire (gzip, the way a host serves it) and
  fails over 25 MB. The dev server binds the address it hands back (vite's
  `localhost` is `::1` only on Windows), logs to a file rather than a pipe
  nobody drains, and is tracked in a pidfile whose pid only counts while its
  image is node's. `web_run` runs files inside the project only and refuses
  `.ts`, which Node 20 cannot execute. The templates ship `telemetry.ts` on
  the Godot autoload's wire contract, discovering a live recording through
  the vite proxy.
- **The Unity engine: adopted through the Hub's project, compiled in
  batchmode, tested through the Test Framework, photographed by the editor,
  instrumented by a self-booting MonoBehaviour.** Never scaffolded: the Hub
  makes a Unity project with a version and a render pipeline the user
  chose. `bgate_adapters/unity.py` finds editors through `BGATE_UNITY` and
  the Hub's install roots and prefers the version `ProjectVersion.txt`
  names, because a newer editor upgrades a project the moment it opens it.
  `check_project` is a batchmode open with the compile errors parsed out of
  the log (file, line, CS code); `test_run` scores the NUnit XML, including a
  truncated one; `screenshot` renders a scene's camera through a bundled
  editor script (a still of the saved scene, not a frame of play); every
  call refuses while `Temp/UnityLockfile` says another editor holds the
  project. `Assets/BGate/BGateTelemetry.cs` boots itself on the first scene
  load and writes the same JSONL the Godot autoload writes. Tested against a
  fake editor at the seams the adapter reads; not against a real install.
- **`engine_status`, `engine_check`, `engine_screenshot`, `engine_scaffold`,
  `engine_templates`, `project_set_engine`: the engine-neutral spine.**
  Additive, not a rename: `godot_status` and its siblings are named in 161
  places including the CLAUDE.md stamped into every user's game. The neutral
  tools ask whichever engine the project records and say on every result
  whether the row agrees with the files on disk, because a row that
  disagrees presents as "the tools are all missing".
- **Atlas builds 3D scenes: a three.js viewport with orbit, selection, a
  move/rotate/scale gizmo and staged writes.** The builder was 2D by
  construction; a 3D project's main scene opened to twenty-nine TypeErrors
  and a blank pane. `bgate_core/level/scenedraw3d.py` walks the tree the way
  the engine does, accumulating each Node3D's world matrix from `transform =`
  (twelve numbers, basis ROWS then origin, which read as columns gives the
  inverse rotation) or from position/rotation/scale (YXZ euler), and resolves
  what each node draws into shapes a WebGL viewport can build: primitives
  with Godot's defaults, collision as wire, lights, the camera, `.glb`
  instances, nested `.tscn` instances with the host's overrides folded in.
  `sceneview.js` probes `/api/scene/render` and hands over to
  `sceneview3d.js` on `dimension: "3d"`; a staged move writes back in the
  spelling the node already uses, so Godot never sees both. One WebGL context
  for the life of the page, eight lights lit and the rest as glyphs (a
  forward renderer with 265 point lights compiles a shader that takes the
  tab down), one fetch per model. Measured on a real driving study: 5,483
  nodes, 265 lights, 1.65 M vertices.
- **The file's own meshes: ArrayMesh geometry decoded from the .tscn's
  base64 surfaces and served per mesh.** A saved 3D scene carries its
  ArrayMeshes inline; the driving study's 75 MB `main.tscn` holds 115. The
  AABB is read during the sub-resource pass and the positions decoded on
  demand through `/api/scene/mesh` (binary): a planar block at the head of
  `vertex_data`, `count x 8` bytes of uint16 fractions of the AABB when
  `COMPRESS_ATTRIBUTES` is set, `count x 12` float32 otherwise, indices
  uint16 up to 65,536 vertices. Verified on all 115: every decoded mesh sits
  inside the AABB the file states. An external `.res` mesh draws as a
  placeholder sized by its sibling collider.
- **The first-run card offers Godot, Web and Unity; Unity as an adopt path;
  `bgate init --engine web`; `POST /api/project/adopt`.** Picking Unity turns
  the template row into a folder field and an Adopt button, backed by the
  same additive adopt the CLI runs; `/api/project` lists every driven engine
  and marks the adopt-only ones.
- **The 3D character pipeline: quadruped poses, `godot_character_wire`,
  `godot_clip_capture`, `godot_clip_retarget`.** Four-legged pose templates
  beside the humanoid ones; a wire that takes an animated `.glb` to a
  proven-playable `CharacterBody3D` scene with an animator and foot IK and
  probes it on a ramp; clip capture in the engine rather than in Blender;
  retargeting through Godot's own BoneMap.
- **The 3D viewport renders on demand and can be stopped; the exe build
  checks and smokes its assets.** Frames are drawn only when something asked
  for one (orbit, gizmo, a model arriving, a toggle); `live` is the
  sixty-a-second mode for anything that animates; `stop` drops the scene and
  loses the context on purpose so the driver frees its memory, `start`
  rebuilds from the server's cache. `build_exe.py` refuses to build without
  `sceneview3d.js` and the vendored three modules, and the smoke test fetches
  them from the bundle.

### Changed
- **Seat lanes, playtest, the Tests tab, the asset scan and the dashboard's
  engine card follow the project's engine.** The default lane table is Godot
  vocabulary (`scenes/**`, `*.godot`); re-rooted at a web project it still
  owned nothing and the hook refused every agent on `src/`. `ENGINE_LANES`
  says the same ownership split in each engine's layout. `playtest_start`
  launches the dev server and a browser tab for web, opens the editor with
  `BGATE_TELEMETRY` set for Unity, and knows each engine's telemetry file;
  the Tests tab runs vitest and the Test Framework into the same history
  `godot_test_run` writes; the asset scan reads `.ts`/`.html` references and
  follows Unity's `.meta` GUIDs; `/api/engine/status` and `/api/engine/check`
  feed the Tech pane, and the Godot workspace routes answer 409 with the
  engine's name on another engine's project.
- **The scene draw list is memoised on the text, the render on the files it
  reads: a 5,483-node scene opens in 0.1 s after the first 5.** One render
  asked for the parse of a 75 MB file five times through five entry points.
  `scenewire.parse` and the sub-resource pass are keyed on the string's hash,
  the render on the host file's stamp plus every instanced scene and model
  it reads, and the decoded meshes are kept under a byte budget. Every cache
  takes a lock: the viewport fires a hundred mesh requests at once onto the
  thread pool.
- **Every seat carries the engine-neutral tools; web and Unity families go to
  the seats that were measured using their Godot equivalents.** A seat brief
  on a web project told every seat to call `engine_check` and the seat gate
  registered none of them.
- **Dependency floors raised above their advisories, and audited at the floor
  in CI.** The declared floors admitted 23 known-vulnerable versions between
  them; `security.yml` audited only the resolved tree, which is the newest of
  everything. It now audits both, and `scripts/dep_floors.py` derives the
  pins from `pyproject.toml`.
- **Templates live under `templates/<engine>/<kind>`.** The dimension was the
  template key, which cannot express two engines. The engine's `shared/`
  tree is what adopt stamps, so an adopted web game is briefed on npm and
  `web_build`, not on `project.godot`.

### Fixed
- **A running game could not report telemetry: the guard refused the proxied
  origin and the tokenless POST.** Measured against the exe: 403 on
  `Origin: 127.0.0.1:5173`, 401 without a token. Neither the Godot web export
  in the `/play` iframe nor a vite dev server can carry the dashboard token.
  The events ingest alone is open to loopback POSTs; start, stop and promote
  keep the token, and the routes smoke reads the exemption from the guard.
- **`engine_screenshot` spread an async tool wrapper's coroutine into a
  dict.** `server._tool` wraps every tool in an async function; the neutral
  dispatcher called the registered names and every Godot and Unity call
  failed with a TypeError. It calls `__wrapped__`, with a test that would
  catch a dispatcher handing back a coroutine.
- **Node subprocesses decoded as cp1252 on Windows and handed back an empty
  stdout for a green vitest run.** vitest prints its ticks in UTF-8 whatever
  the console codepage; the decode error surfaced inside subprocess's reader
  thread and the suite that had just passed 7/7 reported nothing.
- **The dev server's stdout was a pipe nobody drained; a recycled pid could
  get its tree killed.** Past 64 KB of HMR output vite blocked on write and
  stopped serving; a stale pidfile could name whatever the OS handed that pid
  to next, and `dev_stop` killed the tree under it.
- **The Unity Test Framework's `-runTests` was combined with `-quit`, so a
  green suite wrote no results.** `-quit` ends the editor before the
  asynchronous run begins; the runner exits on its own.
- **The character probe's IK weight read 0.00 for every NPC; Blender's
  self-intersection baseline kept the last keyed pose.** `CharacterBody3D`
  updates `is_on_floor()` only inside `move_and_slide()`, and a character
  wired with no controller has nothing calling it; the probe settles an
  unscripted body under gravity. Clearing an action does not move pose bones
  back, so with `clips=[walk, pickup]` the rest count carried pickup's
  overlaps and a colliding walk passed by under-counting.
- **Managed blocks stamped by an earlier release were doubled by
  re-adopting; Unity's Library tree was scanned as the game.** The marker's
  wording was tidied; the legacy spelling is recognised and rewritten so the
  file converges on one block. `Library`, `Temp`, `Logs`, `obj` and
  `UserSettings` are skipped by adopt's scan and the asset scan.
- **An instance's placement stacked on the packed root's transform; caches
  raced on the thread pool; `engine_status` lost the Godot project path.**
  The instance node IS the other scene's root: a `transform =` on the
  instance replaces what the saved root carried. `engine_status` seeded
  `project: None` over the probe's answer and the Tech pane said no
  `project.godot` was found on every Godot project.

### Security
- **Every optional path argument on the web and Unity tools is contained;
  the headless browser visits loopback URLs only; `dist` must resolve inside
  the project.** `web_status` and `unity_status` answered questions about any
  directory on the machine; `web_payload` could measure any directory; a
  headless Chromium pointed at an arbitrary URL returns the page, its console
  and every failed request, which is a read of an internal service through a
  screenshot tool. Checked before the browser probe, so it is refused without
  Playwright installed.
