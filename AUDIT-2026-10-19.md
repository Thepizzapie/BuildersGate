# Builders Gate — security, secrets & code-quality audit

Scope: `Thepizzapie/BuildersGate` @ `47451cb` (v0.1.46) — 1,350 tracked files,
187k lines of `src/`, 89k lines of tests, full 119-commit history.

## 1. Secrets & PII — CRITICAL section: **nothing found**

**No live credentials in the working tree or anywhere in git history.** This is
an explicit confirmation, not an absence of effort:

| Check | Result |
|---|---|
| Key-format scan (`sk-`, `sk-ant-`, `ghp_`, `github_pat_`, `AKIA`, `AIza`, `xox[bapr]-`, `glpat-`, `dop_v1_`, `hf_`, `npm_`, JWTs, PEM blocks) over all tracked files | Only detector patterns + fake fixtures |
| Same scan over `git log --all -p` (every commit, every branch) | Only test fixtures |
| Sensitive filenames in tree (`.env`, `*.pem`, `*.key`, `*.p12`, `id_rsa`, `.netrc`, `.pypirc`, keystores) | None — only `.env.example` |
| Same filenames ever added in history (`--diff-filter=A`) | None |
| `.env.example` contents | All values blank; optional vars commented out |

Every pattern hit resolves to one of two intentional sources:

- `src/bgate_core/board/streamer.py` — the log **scrubber's own** detector
  patterns (lines 129–175). A secret-redaction module naturally contains every
  token prefix.
- Test fixtures that are self-evidently fake: `sk-do-not-leak-this-value`,
  `AKIAIOSFODNN7EXAMPLE`, `xoxb-NOTAREALTOKEN-…`, `ghp_AAAA…`,
  `sk-test-DO-NOT-USE-…`.

**No real PII.** Emails found are a vendored `codemirror/LICENSE` author line
and fixtures (`hunter2@github.com`, `someone@someone.tmi.twitch.tv`). Home
paths are a consistent cast of fictional personas — `marta`, `nina`, `robin`,
`x`, `you`, `someone`, `RUNNER` — never a real account. IPs are all loopback,
the CGNAT test range (`100.64.0.x`), RFC1918 fixtures, or `169.254.169.254`
appearing *inside SSRF-guard tests* for the cloud metadata endpoint.

**Nothing public that shouldn't be.** `.gitignore` covers `.env`/`.env.*`
(un-ignoring only `.env.example`), `.bgate/`, `.claude/`, `.pulsiron/*`,
export presets and build output. Only deliberate examples are tracked
(`.claude/launch.json.example`, `.pulsiron/panels/*`). `docs/decisions/` (27
ADRs) is published documentation by design.

### The one thing to act on here

`.github/workflows/security.yml` states in its own comments that this repo
**"has already had once (a committed API key)"** and recommends GitHub's native
secret scanning with push protection. Current history is clean — earliest commit
is 2026-10-01, so that key is not reachable from any branch today. But:

1. A key that was ever *pushed* must be treated as compromised and rotated,
   regardless of a later history rewrite. Unreachable objects can persist on
   GitHub's side and in forks.
2. Push protection is a **repository setting**, not a workflow — nothing in the
   repo can prove it is on. Verify under Settings → Code security.

## 2. Code Quality

**The baseline is genuinely strong**, and that's worth stating before the
findings:

- `ruff check .` (project config, `E9,F`) — **passes clean**. Zero unused
  imports (`F401`), zero unused variables (`F841`) across 187k lines.
- **Zero** `TODO` / `FIXME` / `HACK` / `XXX` in `src/`.
- Test suite: **7,360 passed, 90 skipped, 1 failed** (`-m "not slow"`, 7m45s).
- Dependency floors are treated as a security control with a comment explaining
  why, and `security.yml` audits **both** the resolved tree and the declared
  floors in separate venvs — because a floor-only vulnerability is invisible to
  a resolved-tree audit. That reasoning is better than most projects manage.
- The dashboard's auth middleware (`src/bgate_ui/api.py:456+`) reasons
  explicitly about **DNS rebinding**, makes the Host gate non-optional even
  under `BGATE_NO_AUTH`, and both remote entry points hard-refuse to start when
  `BGATE_NO_AUTH` is set (`app.py:2429`, `window/desktop.py:165`). Verified, not
  assumed.
- `tests/ui/test_routes_smoke.py` enumerates `app.routes` rather than a
  hardcoded list, so a route added tomorrow is smoke-covered tonight — and it
  recurses through `include_router` because Starlette 1.0 stopped flattening,
  which had silently shrunk coverage from 159 routes to 39.

### Findings

**C1 — Deprecated Pillow API at 31 call sites, with no version cap.**
`Image.getdata()` is deprecated and **removed in Pillow 14 (2027-10-15)**.
`pyproject.toml` declares `Pillow>=12.3.0` with no upper bound, so a future
`pip install` resolves to a Pillow that breaks image analysis. Sites include
`bgate_adapters/blender.py:2090`, `sprites.py:168,389`, `bgate_mcp/server.py`
(5 sites), `bgate_core/level/roomqa.py:282`, `cine/cinecut.py:621`,
`art/chroma.py:146,159`. The test run surfaces this as a `DeprecationWarning`
today.

**C2 — High-severity frontend advisory that CI cannot see.**
`frontend/package-lock.json` (tracked) resolves `source-map-js` 1.0.0–1.2.1:
**high severity**, GHSA-68fv-2mgg-jv7q (event-loop DoS via indexed source-map
section offsets), fixable with `npm audit fix`. Exposure is build-time/dev-server
(transitive under vite/postcss), not the shipped bundle. The real issue is
structural: `ci.yml` runs `npm ci`, `npm run build` and Playwright e2e, but
**never `npm audit`** — so the rigorous two-pronged Python audit has no
JavaScript counterpart, and this is precisely the failure class `security.yml`
was built to catch.

**C3 — One failing test, launcher-coupled.**
`tests/adapters/test_web.py::TestDevServerBookkeeping::test_our_own_process_reads_as_ours_by_image_name`
asserts `web._image_name(os.getpid()).startswith("python")`. Invoked via the
`pytest` console script the process image name is `pytest`, so it fails. CI uses
`python -m pytest` (`ci.yml:238,269`) and is therefore green. This is a brittle
assertion coupled to how the suite was launched, **not a product bug** — but a
contributor running bare `pytest` sees a red suite.

**C4 — Behavioral depth on the HTTP surface.**
All 335 routes under `src/bgate_ui/routes/` get automatic smoke coverage (C.f.
`test_routes_smoke.py` — pass bar is "handler ran, answered in the envelope, no
5xx"). But ~174 of 335 have **no assertion-level test referencing their path**,
concentrated in `chat.py`, `brainstorm.py`, `cinematic.py`, `cutoutedit.py`,
`agent_fleet.py`. Separately, `tileset_synth` (~177 lines) and
`godot_retarget_check` in `bgate_mcp/tools_level.py` have zero test references
of any kind.

**C5 — Silently swallowed exceptions.**
1,223 `except Exception` handlers in `src/`, of which **285 end in a bare
`pass`**. Concentrated in `src/bgate_mcp/server.py` (35) and
`src/bgate_ui/agents/dispatch.py` (27). Many are legitimately best-effort, but
at this density they erase the diagnostic trail for whoever debugs a silent
no-op later.

**C6 — Module size.**
`src/bgate_mcp/server.py` is **11,240 lines**; `bgate_adapters/blender.py` 6,466;
`godot.py` 4,045; `bgate_ui/agents/dispatch.py` 3,523. The two largest are also
the two worst for C5 — not a coincidence worth ignoring.

**No dead code found.** `ruff --select F401,F841` is clean; the module-name
heuristic that first suggested untested modules proved misleading once route
paths and tool names were checked directly.

## 3. Suggested Enhancements — prioritized

**1. Add `npm audit` to CI, and run `npm audit fix` now.** *(security, highest
leverage)* One step in `ci.yml`'s frontend job —
`npm audit --audit-level=high` — closes C2 and gives the JavaScript side the
same guarantee `pip-audit` already gives Python. Cheap, and it catches the next
one too.

**2. Confirm GitHub secret scanning + push protection, and rotate any
previously-pushed key.** *(security)* `security.yml` already argues for this and
explains why it beats a scanning action: it covers the whole history and
*refuses the push* instead of reporting the key after it is public. It cannot be
verified from inside the repo — someone has to check the setting. Pair it with
rotating the key the workflow says was once committed.

**3. Cap `Pillow<14` today; migrate the 31 `getdata()` sites after.**
*(correctness / forward-compat)* The one-line cap in `pyproject.toml` stops a
future resolver from silently breaking image analysis; the migration to
`get_flattened_data()` removes the cliff instead of deferring it. Doing the cap
first means the deadline stops being urgent.

**4. Make the `_image_name` assertion launcher-agnostic.** *(maintainability)*
Accept the running interpreter's actual basename (or assert the name is
non-empty and not in the allowed set, which is what the test is really about).
A green suite under both `pytest` and `python -m pytest` costs one line and
removes a false alarm for every new contributor.

**5. Align `serve(--remote)` with the desktop path's narrower bind.**
*(hardening)* `app.py:2449` sets `bind_host = "0.0.0.0"` roughly twenty lines
after a comment promising "never 0.0.0.0", while `window/desktop.py:178` does
the same job with two pre-bound sockets (loopback + the tailnet IP). This is
**not an open hole** — remote is opt-in behind `--remote`, `remote.enabled()`
requires the Settings switch, and the Host allow-list plus per-device token gate
every request. But `serve` exposes the port on every interface where the desktop
path does not, so an attacker reachable on the LAN gets to argue with the gates
instead of being refused at the socket. Adopt the pre-bound-socket approach in
`serve`, and correct the contradicting comment either way.

**6. Reduce the silent-`pass` density in `server.py` and `dispatch.py`.**
*(maintainability)* Not a rewrite: log at debug in the 62 handlers in those two
files so a swallowed failure leaves a trace. This naturally pairs with splitting
`server.py` (C6), where the handlers are densest.
