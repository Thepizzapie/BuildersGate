### One file that should not be public

`.github/instructions/codacy.instructions.md` is **tracked, and it was meant to be ignored.**
`.gitignore:54` reads:

```
.github\instructions\codacy.instructions.md
```

Backslashes are escape characters in gitignore patterns, not separators, so this
pattern resolves to `.githubinstructionscodacy.instructions.md` and matches nothing.
`git check-ignore` confirms the file is not ignored.

It contains no secrets, but it is a vendor-generated, repo-wide agent directive
(`applyTo: '**'`) instructing any coding agent to install and run a third-party
CLI and to analyze every edited file, calling failure to comply *"a critical error."*
On a public repo, that silently applies to everyone who clones it.

Fix — use forward slashes, then untrack:

```bash
sed -i 's#^\.github\\instructions\\codacy\.instructions\.md$#.github/instructions/codacy.instructions.md#' .gitignore
git rm --cached .github/instructions/codacy.instructions.md
```

### Verified non-issues

These three look alarming to a scanner and are not problems:

- **`shell=True`** at `src/bgate_ui/agents/claudeusage.py:142` runs the user's *own*
  previously-configured `statusLine` command from their `~/.claude/settings.json`.
  A statusLine entry is by definition a shell command string the user wrote. No
  external input reaches it.
- **`bind_host = "0.0.0.0"`** at `src/bgate_ui/app.py:2394` is reachable only via
  opt-in `--remote`, and is gated by a Host allowlist, a separate phone token,
  reverse-proxy header detection, and a path allowlist that deliberately excludes
  `/` so the desk token in the page HTML can never be read remotely. It also
  refuses to start if `BGATE_NO_AUTH` is set.
- **63 ruff `S608` "possible SQL injection"** are all *column-name* interpolation
  from in-code allowlists (e.g. `_RUN_FIELDS` in `board/queue.py`) with values
  always bound as `?` parameters. Checked by hand across `board/jobs.py`,
  `board/queue.py`, `qa/playtest.py` and `store/db.py`. No user input reaches SQL text.

Auth primitives are correct: `secrets.token_urlsafe(24)`, `secrets.compare_digest`
for comparison, `chmod 0600` on the token, remote token and env file.

## 2. Code Quality

The baseline here is unusually high, so the findings below are about gaps in
*enforcement*, not about bad code.

**What is already right**

- 6,308 test functions across 325 files.
- **2** `TODO`/`FIXME`/`XXX` markers in 227k LOC of first-party source.
- `vulture --min-confidence 100` finds **5** dead items, all unused locals:
  `recorder.py:530` (`time_info`), `three_d/cutoutkit.py:670` (`rig_height_px`),
  `bgate_mcp/server.py:5168` (`next_cost`), `agents/runners.py:256` and `:326`
  (`auto_approve`, documented as deliberately inert at `runners.py:356`).
  Essentially no dead code at 195k LOC.
- Dependency handling is better than most commercial repos: floors are treated as
  a security control and `security.yml` audits *both* the resolved tree and the
  pinned floors, because a floor-only vulnerability is invisible to a resolved run.
  Dependabot covers pip and github-actions. CodeQL runs on the default suite with
  a written rationale for not using `security-and-quality`.
- SQLite configuration is correct for the concurrency this tool actually has:
  WAL, `synchronous = NORMAL`, an explicit `busy_timeout`, a per-thread connection
  cache, and 74 indices.
- 8 `async def` route handlers total; none performs blocking DB or subprocess work,
  so nothing stalls the event loop. The remaining routes are sync `def`, which is
  the correct choice under FastAPI's threadpool.

**Gaps**

1. **`npm run typecheck` is defined and never runs in CI.** `frontend/package.json`
   declares `"typecheck": "tsc --noEmit"`; no workflow invokes it. `ci.yml` runs
   `lint`, `frontend-drift`, `browser-smoke` (Playwright e2e), `test`, `test-linux`
   and `wheel-smoke` — but never `tsc`. This is precisely the gap the `ci.yml`
   header comment celebrates closing for ruff: *"pyproject has carried a
   deliberately-chosen ruff rule set since someone picked it. Nothing in CI
   invoked it."* 31.8k LOC of TypeScript currently has no type gate.
   **I ran it: `tsc --noEmit` exits 0 today.** Wiring it in is free and green
   immediately.

2. **1,220 broad `except Exception` handlers in `src/`, of which 331 swallow
   silently** (`S110` try-except-pass ×302, `S112` try-except-continue ×29).
   Hotspots: `bgate_mcp/server.py` (44), `bgate_ui/agents/dispatch.py` (31),
   `agents/followup.py` (13), `board/queue.py` (13), `bgate_ui/app.py` (12).
   Much of this is defensible — this is a tool that shells out to Godot, Blender
   and agent CLIs, and `jobs.progress()` is explicitly *"best-effort by design"*.
   But at 331 silent handlers, a real bug in a dispatched-agent path has many
   places to hide with no log line, and this codebase has no counterweight: there
   is no debug-level logging behind these.

3. **`src/bgate_mcp/server.py` is 11,357 lines** and costs 219 ms of self-time to
   import (900 ms total, 477 ms of which is the `mcp` library itself). It registers
   251 tools. This is the single highest-friction file in the repo for both review
   and startup latency. `tools_level.py`, `tools_cinematic.py`, `tools_research.py`
   and `tools_reuse.py` already demonstrate the extraction pattern.

4. **`SECURITY.md`'s threat model predates `--remote`.** It states the dashboard
   *"binds to `127.0.0.1`"* and *"Do not put it behind a reverse proxy."* Both
   are now contradicted by the shipped `bgate app --remote` / `bgate serve --remote`
   path, which binds `0.0.0.0` and explicitly documents
   `tailscale serve --https=443` as the supported HTTP-proxy configuration.
   The implementation is sound; the policy document simply does not describe it,
   so a reader cannot evaluate the feature's actual exposure. Zero mentions of
   "remote", "tailscale" or "tailnet" in `SECURITY.md`.

5. **Two dangling references.** `SECURITY.md:65` points readers at
   `docs/qa-nitpick-audit.md`, which is not in the repo. And `README.md:24` says
   *"There is no spend ceiling and no ledger."* The dollar ledger is indeed gone
   (dropped in the migration at `store/db.py:348`), but `queue.spend_paid_call()`
   enforces a live, hard **paid-call** ceiling — 30 per work item by default — that
   returns `budget_exceeded_item` and stops the agent. A user reading the README
   has no way to anticipate that.

## 3. Suggested Enhancements

Ordered by value for effort.

### 1 — Fix the gitignore pattern and untrack the Codacy file *(security, ~2 min)*
The only thing in the repo that is public against its author's intent. One `sed`
and one `git rm --cached`, shown above.

### 2 — Add a `typecheck` job to `ci.yml` *(maintainability, ~10 min, green today)*
Verified passing. Slots in beside `frontend-drift`, which already installs Node:

```yaml
  typecheck:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: "20"
          cache: npm
          cache-dependency-path: frontend/package-lock.json
      - run: npm ci
        working-directory: frontend
      - run: npm run typecheck
        working-directory: frontend
```

### 3 — Enable GitHub secret scanning with push protection *(security, ~1 min)*
`security.yml`'s own header already argues for this and records that the repo
*"has already had"* a committed API key once. History is clean today — I verified
that — but the control that prevents a recurrence is a repository setting, not a
workflow, and nothing in the repo can confirm it is on. Settings → Code security →
Secret protection. Free on public repos, scans all history, and refuses the push
rather than reporting the key after it is already public.

### 4 — Document `--remote` in `SECURITY.md`, and fix the two dangling claims *(security docs, ~30 min)*
Add a "Remote mode" subsection to the threat model covering what the tailnet side
can reach (`/api/`, `/play/`, `/favicon`), what it can never reach (`/`,
`/api/remote`, `/pair`), the separate phone token, why `tailscale serve --tcp` is
refused while `--https` is supported, and the `BGATE_NO_AUTH` interlock. The code
comments in `api.py:330-400` and `app.py:2367-2399` already contain the entire
argument — it just needs to live where a security reader will find it. While there,
drop the `docs/qa-nitpick-audit.md` reference and add one clause to `README.md:24`
noting the paid-call ceiling.

### 5 — Give the silent handlers a voice before splitting `server.py` *(maintainability)*
Both items 2 and 3 of the Code Quality section point at the same risk, and the
cheap half comes first. Add a module-level logger and convert the 331 bare
`except … : pass` / `continue` sites to `logger.debug("...", exc_info=True)`,
starting with `agents/dispatch.py` and `bgate_mcp/server.py` where dispatched-agent
failures currently vanish. A `--debug` flag on `bgate serve` that raises that
logger to stderr would make the next agent-path bug diagnosable from a user's
report instead of a reproduction. Extracting `server.py` into `tools_*.py` modules
is the larger follow-on, and is much safer to attempt once failures in those paths
are visible.
